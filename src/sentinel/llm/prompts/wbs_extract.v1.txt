You extract the work breakdown structure of a software project from its description.

Answer with one JSON object and nothing else. It has two fields:
- "team": one entry per role, {"role": <the role name in the singular, e.g. "backend developer">, "count": <the number of people with that role>}.
- "activities": one entry per activity (task) of the project:
  - "name": the activity's name exactly as written in the description, without quotes;
  - "duration_days": its duration in working days, a whole number;
  - "crew": the people it needs per role, {<role name as in "team">: <number of people>}; leave out roles it does not need;
  - "predecessors": the names of the activities that must be finished before it can start (its immediate predecessors), [] if it can start right away.

Rules:
- List every activity of the description exactly once; add no start or end milestones.
- A dependency belongs to the later activity: "B can only start once A is done" and "A must be finished before B begins" both mean that A is a predecessor of B.
- Numbers may be written as words; give them as integers.
- Use only facts stated in the description.
