## Summary
The forecast study replays the WP2b NoReaction worlds and records observations at
f ∈ {0, 0.2, 0.4, 0.6, 0.8} of the plan without changing the worlds. At each checkpoint it
runs `mc_full`, `mc_no_future` and the deterministic plan-based estimate, and
`forecasts.csv.gz` keeps their scores against the realised makespan, never the samples. The
metrics of the new spec §5.2 come from that file with cluster-bootstrap intervals:
`summary.md`, LaTeX tables and reliability, Brier and PIT figures, regenerated by
`sentinel summarise-forecasts`. Every summary checks the worlds against WP2b. Both smoke runs
produced all outputs with 0 mismatches. Measured estimates for the full runs are 2.5 h (main)
and 13 min (misspecified priors), so no reduction was needed.

## Decisions
- **Observations** are a by-product of `simulate`: they live in a result field left out of serialisation. The 50-run regression digests and every dump are therefore unchanged. A recording policy with T_r = 1 would change `n_epochs` (ADR-0010).
- **WP2b worlds.**
  - Same seed rule, and max_days of δ_D = 0.3, the largest slack of WP2b.
  - The check compares makespans and seeds per (set, instance, scenario, replication).
  - The WP2b file path is in the configs (`wp2b_results`).
  - 0 mismatches in all 540 worlds checked: smoke runs 160 + 20, timing samples 320 + 40.
- **Skip rule:** C ≤ t_f. On the completion day the observation shows all real work done.
- **Forecast seed:** derive_seed(2026, "forecast", set, instance, scenario, r, f), shared by the forecasters. With `forecast`'s rollout CRN, `mc_full` and `mc_no_future` share their belief samples.
- **Deterministic forecaster** (written into §5.2):
  - the floor of one crew-member day is applied before every observed shock and at the end;
  - an absent worker returns at s + max(L_low, t − s + 1);
  - its seed is recorded only; it yields a point mass (CRPS = |Ĉ − C|, PIT pair in {0, 1}).
- **Priors override:** the observation's `pert` and `disruptions` are replaced, so belief and future change together. κ scales λ_A, λ_S and λ_N only; the widened PERT keeps λ = 4 and also drives D3 durations in the future.
- **Metric details** (notes):
  - Bins are [k/10, (k+1)/10) with the last closed and an edge tolerance of 10⁻⁹.
  - Sharpness is the population variance; the log score uses natural logs.
  - CRPS is computed exactly for the empirical CDF; quantiles use `inverted_cdf`.
  - Coverage includes both ends; the randomised PIT has its own seed (2026).
  - Early warning runs per (world, forecaster) over non-skipped checkpoints.
- **Intervals:** one resample matrix per set (1,000 resamples, seed derive_seed(2026, "bootstrap", set)), shared by all statistics, so differences are paired. Every statistic is a ratio of per-instance sums. Cells are pooled over λ_A and also over checkpoints ("all"), never over sets.
- **Outputs:**
  - Appendix tables `<table>_delta0.3.tex` and `<warning_table>_delta0.3.tex`.
  - The misspecification config names its own tables and figures (`table_wp3_misspec*.tex`, `fig_wp3_misspec_*`).
  - Figures use the categorical slots of the dataviz reference palette in fixed order, with markers. Node is not installed, so the palette validator could not run; the slots are used unchanged, and the fourth (misspec) is backed by markers.
- **Granularity:** one pool task per instance (30–60 s each). The progress line waits for the first finished instance before extrapolating.
- **CLI** imports the summary module lazily, so `sentinel inspect` and `baselines` do not load matplotlib.
- ADRs created: ADR-0010 (forecast study layout).

## Spec questions
1. **Early warning at f = 0** (§5.2). A run counts as warned if p < θ at any checkpoint, f = 0 included. At δ_D = 0.2 most runs are late, so a calibrated forecaster reports p near the base rate on day 0, below θ = 0.5 for most runs. In the smoke run `mc_full` therefore warned 97–100 % of late runs, but also 80 % (J30) and 89 % (J60) of on-time runs at θ = 0.5. The deterministic forecaster warned 65 % / 56 % of late runs with 0 % / 7 % false alarms. Implemented as written. Should warnings start at f = 0.2, or require two consecutive checkpoints below θ?
2. **Deterministic remaining work after an overrun** (§5.2). The prompt says max(p_j − e_j, one crew-member day) "with shocks applied by their factors". Reading used: the floor applies before each shock, R_i = max(R_{i−1} − Δe, 1/M_j) · F_i. Without it, an activity that overran before a shock would be replayed with negative remaining work. Please confirm.
3. **Absent workers past their announced bound** (§5.2). Reading used: the return day is s + max(L_low, t − s + 1), i.e. tomorrow once the bound has passed. This is the smallest admissible L of §5.1. Please confirm.
4. **Skip rule** (§5.2). Reading used: C ≤ t_f. A checkpoint on the completion day is skipped, because all real work is done at its step 3. Please confirm.
5. **D2 compounding (observation).** Under §2.2, remaining work R grows by λ_S (E[F] − 1) R − 1 per work day in expectation. Above R* = 1/(λ_S (E[F] − 1)) it tends to keep growing: 167 full-crew days at λ_S = 0.01, 83 at κ = 2. One of the 20,000 `mc_k2` rollouts in the misspec smoke run reached max_days = 280 (j302_3, f = 0); the other 79,999 rollouts of that run and all 320,000 of the main smoke run finished in time. There, a 9-person activity of nominal 10 days had grown to 170 days of remaining work. Truncated rollouts count as max_days and as late, so they enlarge CRPS and the mean but cannot make p wrong. No world was ever truncated in WP2b. Is the heavy tail intended?
