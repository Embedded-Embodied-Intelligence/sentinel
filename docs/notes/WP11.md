# WP11 notes — the AI features of the application with real models

Material for the course report (application chapter) and, briefly, the article's discussion of
the LLM roles in practice. All runs: `scripts/ai_live.py`, logs and screenshots in `docs/qa/ai/`.

**Setup.** The three roles of spec section 10 inside the application (spec section 11): a project
described in words (WP6a extraction with up to three repair rounds), a check-in message turned
into events (spec section 10.2) and an explanation of a recommendation with its faithfulness
check (section 10.4). Two inputs of 12 tasks each in Polish: a structured list and free prose,
scored against what the text states. A message with two facts: "Ania jest chora do piątku, a
logowanie zajmie jeszcze 3 dni dłużej" ("Ania is ill until Friday, and the login will take 3 more
days"). Models: `qwen2.5:7b` on Ollama on a 4-core CPU without a GPU, and `openai/gpt-oss-120b`
served by Groq through OpenRouter (provider pinned). Caches store no prompts (invariant 7).

Three runs of the local model and one of the cloud model on the final code (inputs, seeds and
temperature 0 identical; a local model on a CPU is not deterministic across runs):

| Flow | qwen2.5:7b, runs 1 / 2 / 3 | gpt-oss-120b |
| --- | --- | --- |
| Structured list: tasks of 12 (durations, crews, predecessors right) | 12 (12, 12, 12) in all three; 45–49 s | 12 (12, 12, 12); 3.6 s |
| Free prose: tasks of 12 (durations, crews, predecessors right) | 12 (12, 12, 9) / 11 (11, 11, 8) / 11 (11, 11, 8); 51–53 s | 12 (12, 12, 12); 3.6 s |
| Message: return of the absent person | Fri 23 Oct / Tue 27 Oct / Tue 27 Oct | Mon 26 Oct |
| Message: growth of "Logowanie" (3 more of 5 days) | +60 % (≈ 3 days) in all three; 4–7 s | +60 % (≈ 3 days); 1.4 s |
| Explanations checked against the data | 2 / 1 / 0 of 2 faithful; 7–13 s each | 2 of 2 faithful; 1–2 s each |
| Tokens in 6 calls, cost | 5,288 / 5,507 / 5,510, free | 7,654, 0.0024 USD |

The unfaithful explanations cite a wrong delay figure or the wrong deciding criterion; none
invents an action (the §10.4 check). Both models write "the project manager chose" or "the
agent selected" for Sentinel's recommendation; the check does not test who decided.

**What the live runs changed.** (1) Without the team's role names the models invented their own
("analyst", "backend developer"), and the review dropped those people silently; the description
now carries the team's roles. (2) `qwen2.5:7b` did the arithmetic of the prompt's rules wrong:
the return "do piątku" as Wednesday 28 Oct (day 17 instead of 14) and "3 more days" of 5 left as
the factor 1.30 instead of 1.60. With the next working days written out with their weekday it
gave Friday in 2 of 4 runs and Tuesday in the other 2; with a table of the factors of 1, 2, 3, 5
and 10 more days it gave 1.60 in all 3 runs. The large model needed neither. The semantics of
section 10.2 are unchanged: the aids only state its arithmetic.
(3) With prompts withheld from the cache (real messages), a repair round cannot show the
previous answer, so its message now says what the issue kind asks for.

**Open reading.** "Chora do piątku" is back on Friday by section 10.2 ("a weekday gives r") and
back on Monday by the natural Polish reading of "until Friday" (absent through Friday).
`gpt-oss-120b` reads Monday; `qwen2.5:7b` read Friday once and Tuesday, which neither reading
gives, twice. The manager confirms each item before it is saved, so a wrong day is visible; the
spec question is in the WP11 report.

**Privacy.** After every run the data directory (database, settings, caches), the server's log
and every served page were searched for the absence reason (`chor`, `sick`, `ill`, `flu`,
`grypa`, `L4`): no match in any run, and every cache record holds no messages.

**Failures.** A local stand-in for the model answered invalid JSON, an HTTP 500, an HTML page,
nothing in time, or was down; each of the four forms (settings test, description, message,
explanation) showed a plain message, kept the text and worked again once the stand-in recovered.
A provider that is down, a timeout and an unreadable description or message are named as such;
an HTTP error or an answer that is not JSON reads "the AI did not answer; try again later". On
the settings page each wrong setting tried is named: no key, a wrong key and a wrong model's name
for Groq and OpenRouter, a wrong model's name and a wrong address for Ollama.
