Run this prompt only after WP0 has been reviewed and approved.

Goal: answer RQ2 — "Does CP-SAT produce better schedules than priority-rule heuristics?" —
on PSPLIB J30 (reference: proven optima) and J60 (reference: best-known upper bounds `hrs`,
plus deviation from LB0, the standard measure of Kolisch & Hartmann 2006). The resulting
table will be shown at the concept presentation, so correctness and reproducibility matter
more than speed of implementation.

Fixture facts: on `tests/fixtures/tiny.sm` LB0 = 7 and the optimum is 7; the serial SGS with
the LFT rule (ties by smallest id) also yields 7.
</context>

<task>
1. **Priority rules** `src/sentinel/scheduling/priority_rules.py` — functions returning a
   priority vector over activity ids (document whether lower or higher is better; ties broken
   by smallest id):
   - LFT (minimum latest finish time, horizon = LB0),
   - LST (minimum latest start time),
   - MTS (maximum number of total, i.e. transitive, successors),
   - GRPW (maximum `p_j` + sum of durations of immediate successors).
2. **Serial SGS** `src/sentinel/scheduling/sgs.py` (Kolisch 1996):
   - `serial_sgs(instance, priorities, *, lower_is_better) -> Schedule`: at each stage pick
     the highest-priority eligible activity (all predecessors scheduled) and start it at the
     earliest time that is precedence- and resource-feasible, using a time-indexed resource
     profile that grows as needed.
   - `regret_biased_sampling(instance, n_schedules, rng, alpha=1.0) -> tuple[Schedule, int]`:
     regret-based biased random sampling on LFT (Drexl 1991; Kolisch 1996). For eligible set
     `EL`, regret `ρ_j = max_{i∈EL} LF_i − LF_j`, selection probability ∝ `(ρ_j + 1)^alpha`.
     Return the best schedule (minimum makespan; ties: first found) and the number of
     schedules generated. Uses only the passed `numpy.random.Generator`.
   - Performance target: 1000 samples on a J60 instance in ≤ ~5 s on this CPU. Measure it;
     optimise the inner loop only if needed, keeping the code readable.
3. **CP-SAT** `src/sentinel/scheduling/cpsat.py`:
   `solve_cpsat(instance, *, time_limit_s, num_workers=1, random_seed=0, horizon=None)
   -> SolveResult` with fields `status` (`OPTIMAL | FEASIBLE | INFEASIBLE | UNKNOWN`),
   `schedule | None`, `makespan | None`, `lower_bound` (best objective bound),
   `wall_time_s`. Model: one fixed-size interval per activity, `AddCumulative` per role,
   precedence constraints, minimise the sink start. Default horizon = makespan of the SGS-LFT
   schedule (a valid upper bound); record this choice in the notes. No solution hints.
4. **Benchmark runner** `src/sentinel/experiments/rcpsp_benchmark.py` with config
   `configs/wp1_rq2.toml`, following the `experiment-run` skill exactly:
   - sets: `j30` (reference `opt`), `j60` (reference `hrs`);
   - methods: `sgs_lft`, `sgs_lst`, `sgs_mts`, `sgs_grpw`, `rbrs_1000` (alpha = 1.0),
     `cpsat_1s`, `cpsat_10s` (CP-SAT: `num_workers = 1`, fixed seed);
   - base seed 2026; `max_workers = 4` processes; `--limit N` smoke mode;
   - `results.csv` columns: `set, instance, method, makespan, lb0, c_ref, dev_ref_pct,
     dev_lb0_pct, matches_ref, status, solver_bound, runtime_s, seed`;
   - every schedule is checked with `validate_schedule`; an invalid one aborts the run;
   - summaries generated by code: `summary.md`; `table_rq2.tex` (booktabs; rows = methods;
     for each set: mean `dev_ref` %, share matching the reference, mean runtime; J60 also
     mean `dev_lb0` %); figure `fig_rq2_deviation.pdf` and `.png` (box plot of `dev_ref` per
     method, one panel per set). Add `matplotlib` as a dependency for figures.
   - print an estimated total duration at start and a progress line every ~10 s.
5. **Tests**:
   - tiny fixture: every rule gives a feasible schedule with makespan ≥ 7; SGS-LFT gives 7;
     RBRS with the same seed returns the same makespan twice; CP-SAT returns `OPTIMAL`, 7.
   - unit: SGS respects precedence and capacity on a hand-made instance where a naive
     earliest-start schedule would overload a resource.
   - `@pytest.mark.data`: SGS-LFT feasible on all 480 J30 instances; CP-SAT with 10 s on
     `j30/j301_1` reaches the PSPLIB optimum.
6. **Smoke run** (do not run the full benchmark in this session):
   `--limit 10` on both sets with all methods. Commit nothing from the smoke run except what
   the report needs to quote.
7. Finish with the `wp-report` skill. In "Commands for the owner" give the exact full-run
   command and your measured-based duration estimate. In `docs/notes/WP1.md` describe the
   rules, SGS, RBRS, CP-SAT model and parameters as implemented, with references.
</task>
