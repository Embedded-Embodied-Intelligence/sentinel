# WP2b — Baseline plans and the NoReaction scenario study

Run after WP2a and WP2a.1 are done (all acceptance criteria PASS). Start a fresh session (`/clear`).

<context>
Read: `CLAUDE.md`, `docs/spec/model.md` (v1.2, especially §1.2, §2, §3, §3.1, §8),
`docs/reports/WP2a.md`, `docs/reports/WP2a.1.md` (calibration table), `docs/notes/WP2a.md`, skills `experiment-run` and `wp-report`.

Purpose: (1) give every instance a reproducible **baseline plan** that all policies start from;
(2) measure how the project behaves when nobody reacts (`NoReaction`) across a grid of
disruption scenarios. This study calibrates scenario difficulty for WP4–WP7: the architect
needs to see in which scenarios NoReaction misses the deadline often but not always, because
those are the scenarios where a reactive agent can make a measurable difference.
</context>

<task>
1. **Deterministic CP-SAT limit.** Extend `solve_cpsat` with an optional
   `deterministic_time_limit: float | None` (CP-SAT parameter `max_deterministic_time`), so
   results do not depend on machine load. Keep the existing wall-clock behaviour as default.
   Add a test that two runs with the same deterministic limit and seed give identical schedules.
2. **Baseline plans** `src/sentinel/simulation/baselines.py`: `baseline_plan(instance, method)`
   with methods `cpsat_det` (CP-SAT, 1 worker, fixed seed, deterministic limit from config)
   and `sgs_lft`. Cache results in `data/derived/baselines/<set>/<instance>.json` (gitignored;
   reproducible) with method, parameters, makespan, status and package versions; recompute if
   the parameters differ. A CLI command `sentinel baselines --set j30 --method cpsat_det`
   precomputes a whole set.
3. **Scenario study runner** `src/sentinel/experiments/simulation_study.py` with config
   `configs/wp2_noreaction.toml` (follow the `experiment-run` skill):
   - sets `j30` and `j60` (all 480 instances each), baseline `cpsat_det`;
   - `C*` per instance = PSPLIB reference (j30 `opt`, j60 `hrs`);
   - scenario grid: `lambda_a ∈ {0.0, 0.0025, 0.005, 0.01, 0.02}` × `mean_absence ∈ {3, 5}`
     (only `3` when `lambda_a = 0`), with `lambda_s = 0.01`, `lambda_n = 0.02`; plus one
     scenario `durations_only` with all disruptions off;
   - replications `R = 20` per (instance, scenario); seed per (instance, replication) shared by
     all scenarios (common random numbers, §2.3);
   - simulate once per (instance, scenario, replication) and evaluate `deadline_met` post hoc
     for every `delta_d ∈ {0.1, 0.2, 0.3}` (the deadline only matters for truncation, so use
     `max_days` from the largest `delta_d` and record any truncation);
   - `results.csv`: set, instance, scenario, replication, seed, baseline makespan, `C*`,
     realised makespan, ratio to `C*`, `met_0.1`, `met_0.2`, `met_0.3`, total cost, cost / `B`
     (with `beta = 0.10`), number of events per type, decision epochs, truncated, runtime;
   - summaries generated by code: `summary.md` and `table_wp2.tex` (per set × scenario: mean
     makespan ratio, P(on time) for each `delta_d` with a 95 % Wilson interval, mean cost / B,
     mean events); figure `fig_wp2_ontime.pdf/.png`: P(on time) vs `lambda_a` (x), one line per
     `delta_d`, panels per set and `mean_absence`.
4. **Smoke run** with `--limit 5` and `R = 3`; measure throughput and give the full-run command
   and a measured duration estimate in the report. Do not run the full study in the session.
5. **Tests**: baseline cache round-trip and invalidation; runner on `tiny.sm` produces the
   expected columns; `durations_only` with `X ≡ 1` reproduces the baseline makespan exactly.
6. Finish with the `wp-report` skill; `docs/notes/WP2b.md` documents the baseline method, the
   scenario grid and the CRN scheme as used.
</task>
