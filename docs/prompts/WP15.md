# WP15 — Interface v2, part 1: Start, Pulpit, Raport with live voice, Decyzja, new-project wizard

Fresh session (`/clear`). Runs overnight; the owner presents on Monday.

<context>
- `CLAUDE.md`, **`docs/design/v2-spec.md` (binding: every rule, label and number in it)**,
  `docs/spec/model.md` §4 (permission gate) and §11, ADR-0025 (front-end stack), ADR-0031 (voice),
  ADR-0032 (dates), `docs/reports/WP12.md` (promise = result, causes), `docs/reports/WP14.md`
- skills `spec-guard`, `adr`, `wp-report`

The owner judged the current interface overwhelming: everything at once, grey, too much text, no
clear place to look. A design workshop produced `docs/design/v2-spec.md`: principles from the
literature, a decision model with the human in the loop, number formats and states, a visual
system, a label glossary and ten screens. This WP builds the first five screens and the shared
parts as **a new interface under `/v2`** on the existing services; the current interface at `/`
stays as it is (it is the fallback for Monday). WP16 builds the remaining screens.
</context>

<task>
Work in this priority order and commit after each step (`WP15: …`), so that if time runs out the
most important screens are finished: 1 → 2 → 4 → 3 → 5 → 6 → 7.

1. **Shell and visual system** (§5, §7): `/v2` routes, `sentinel-v2.css` with the tokens (light
   default, dark, system; cookie-remembered), the sidebar and the project tabs (tabs for WP16
   screens link to a calm "Wkrótce" placeholder for now), the live banner (§7), the dot grid, the
   state badge, the before → after effect chips, buttons. ADR for the v2 design system and the
   coexistence of `/` and `/v2`.
2. **Pulpit** (§4, §8.2): verdict and states with the agreed thresholds (80 / 50), the three
   numbers with "Skąd ta liczba?", the pending decision in place, "Zapas czasu" chart, "Najbliższe
   7 dni", "Przyczyny zmiany", "Główne ryzyka". Spec §11 via `spec-guard` for the states, the
   verdict and the "Zapas czasu" definition.
3. **Decision model in the application** (§3), needed by the next screens: the live project always
   runs the permission gate at the level where every action needs approval (including plan
   re-ordering; research configs untouched); the lifecycle states with time, actor and the brief
   snapshot stored as events; validity date and cost of delay in the background job; reminders
   and "wygasa jutro"; recomputation after a report (`zastąpiona`). Spec §11 via `spec-guard`.
4. **Decyzja** (§8.4): brief with the code-generated contrastive "Uzasadnienie", "Kogo dotyczy",
   "Koszt zwłoki", Zatwierdź / Odrzuć (four reasons; "Inny powód" with the voice text box) /
   Popraw (the one parameter per action type the model can evaluate — check which, and say so in
   the report) / Odłóż decyzję, Szczegóły (all options incl. "Bez zmian", the finish-date
   distribution, the AI explanation on request). The project tab "Decyzje" (pending + this
   project's past decisions). Keep the WP12 promise-equals-result test passing for v2.
5. **Raport** (§8.3) with **the voice component** (§9): recording with ✓/Enter and ✕/Esc, live grey
   preview every ~3 s by Groq Whisper, final transcription to black text on ✓, ✕ removes only the
   dictated span, 5-minute technical cap; hint chips; "Postęp zgodny z planem"; "Do potwierdzenia"
   cards unchecked by default with ✎ and ✕, amber question cards that block saving,
   "Nierozpoznane fragmenty"; "Wpływ na projekt" as a debounced dry-run forecast of the draft;
   the no-news warning; "Wypełnij formularz" fallback. Update ADR-0031 for live preview.
6. **Start** (§8.1): "Decyzje do podjęcia" across projects sorted by validity date, project tiles,
   "Ostatnie zdarzenia" (from the stored lifecycle events), the first-visit cards.
7. **Nowy projekt** (§8.5): the four steps; dictation for the team and the tasks; no
   absence-frequency question — a team-wide default from public Polish absence statistics (find a
   citable source, e.g. ZUS or GUS data on sickness absence; record value, source and reasoning in
   an ADR); budget shown as information with "Zmień".
8. Tests: unit tests for states, verdicts, "na 100" rounding, "Zapas czasu", validity date and
   cost of delay, lifecycle; the internal-term checker and translation tests over v2; the
   accessibility scan on v2 (light and dark); an e2e test of the **demo path** (§10) in demo mode
   with Playwright's fake microphone. Screenshots of every v2 screen built here (PL and EN, light
   and dark, 1440×900 and 1280×800) in `docs/ui/v2/`.
9. Version 1.6.0, rebuild the zip from a clean tree (do not tag), `wp-report`
   (`docs/reports/WP15.md`) with the screenshots of Pulpit, Raport and Decyzja embedded.
</task>
