# WP13 — Remote usability test: scenario check on the demo and the owner's log export

Fresh session (`/clear`). Small WP before the usability test with people.

<context>
- `CLAUDE.md`, `docs/usability/protocol-pl.md`, `docs/usability/results-template.md`,
  `docs/usability/projekt-testowy.csv`, `docs/usability/zespol-testowy.txt`, `docs/deploy.md`,
  `src/sentinel/app/store.py` (event log), `configs/app_demo.toml`
- skills `wp-report`

The owner runs the usability test **remotely and unmoderated**: 2–3 people get a written
instruction (Polish, no jargon) and the CSV file, open the public demo on their own computer and do
the protocol's five tasks in one browser tab, then send back an answer card (clock times per task,
answers, ease 1–5, SUS). Each tester names the project with a code, e.g. "P1 Aplikacja rezerwacji
wizyt". The instruction keeps the protocol's story: project from Mon 2 Nov 2026 to Fri 4 Dec 2026,
today Wed 4 Nov 2026; at the check-in the workshop finished on 3 Nov, "Baza danych i API" is at
about 15 %, Bartosz Kowalski is absent from 5 Nov and back on Mon 16 Nov; task 4 decides on a
recommendation; task 5 runs the small simulator example to the end.
</context>

<task>
1. **Scenario check on 1.4.0 in demo mode** (Playwright, fresh demo data dir, as a tester would):
   run the five tasks with the instruction's inputs. Confirm that task 1 works with the CSV upload
   and the pasted team, that a check-in dated 4 Nov in the past of today's real date is accepted
   without confusing warnings, that **task 4 shows a recommendation** (with the 11 Nov holiday now
   in the calendar), and that task 5 finishes in the demo limits. Fix what breaks for this
   scenario (`WP13 fix:` with tests); update the protocol's expected values (task 4's
   recommendation, success criteria) and `baseline-timing.json` to 1.4.0.
2. **Owner's log export**: `scripts/usability_logs.py --data-dir <demo data dir> --code P1`
   finds the demo sandbox(es) holding a project whose name starts with the code and writes
   `docs/usability/logs/P1.md`: a timeline of that sandbox's events with wall-clock times
   (project created, plan made, check-in saved with its content, recommendation shown, decision,
   simulator runs and advances, errors and refused forms if they are logged), plus derived
   durations per task (task 1 from the sandbox's first request to the plan; task 3 to the saved
   check-in; task 4 to the decision; task 5 to the end of the simulation) and the number of page
   requests and failed form submissions between them, if the app records them. Never write IP
   addresses, session cookies or keys into the output. If the demo records too little for these
   durations, add minimal per-sandbox request logging in demo mode only (time, method, path
   template, status; no addresses, no form contents), documented in `docs/deploy.md`.
3. Tests for the export on a scripted run; `docs/usability/README.md` (owner's steps: before the
   test, after each tester, where the logs land, how to fill `results-template.md` from a log and
   an answer card; SUS scoring by a small script `scripts/sus_score.py` reading the ten answers).
4. Version 1.4.1, rebuild the zip from a clean tree (do not tag), `wp-report`
   (`docs/reports/WP13.md`).
</task>

<constraints>
- No change to research semantics; `reproduce --check` passes. No new runtime dependencies.
- Privacy: logs contain no addresses, cookies or form free text beyond what the tester typed into
  project fields (all fictional by instruction); nothing about absences beyond dates.
- Default `pytest -q` ≤ 90 s; `e2e` separately. Do not restart the public demo; the owner does it.
- Never wait for a process with `pgrep -f <name>` in a shell loop.
</constraints>

<acceptance_criteria>
1. The scenario works end to end in demo mode on 1.4.1, with a recommendation at task 4.
2. `usability_logs.py` produces a readable per-tester log with per-task durations from a scripted
   run; `sus_score.py` scores a sample card correctly.
3. Quality gate, `-m e2e`, `reproduce --check` pass; 1.4.1 zip; pushed; clean tree.
</acceptance_criteria>

<report_format>
`docs/reports/WP13.md` via `wp-report`, with the exact owner commands to export a tester's log.
</report_format>
