<task>
0. **Spec v1.9.2 and architecture** (commit `spec: cache privacy for real data; architecture
   (v1.9.2)`) plus the implementation and a test of answer 2.
1. **Cockpit** `sentinel dashboard` (`src/sentinel/dashboard/`): simulates one project and writes
   one self-contained HTML file. Options: `--set`, `--instance`, `--replication` (WP2b seeds),
   `--lambda-a`, `--delta-d`, `--policy` (any WP4/WP5 policy, default `sentinel_full`),
   `--compare` (a second policy on the same world, default `no_reaction`), `--explain`
   (`template` default, no LLM; or `ollama` / `openrouter` through the cache), `--out`.
   Content, in English with a `--lang pl` option for labels (the presentation is Polish):
   - header KPIs: deadline, realised makespan, on time, cost / B, plan changes, overtime,
     substitutions, escalations — for both policies side by side;
   - Gantt chart: baseline plan vs realised execution (paused days, substitutions, temporary
     workers, inserted activities marked), with event markers (absence, work increase, new
     activity) on a shared time axis;
   - risk chart: the agent's forecast `P(C ≤ D)` and the P10–P90 makespan band at every
     deliberation over time, with the deadline and the realised outcome;
   - decision log: one row per deliberation with day, triggering events, needs, the chosen action
     and its level, the runner-up and the deciding component, `p̂`/`T̂` of both, gate outcome
     (auto / deferred / escalated / approved), and the explanation (template text built only
     from the decision record; LLM text when `--explain` is set, with its faithfulness check
     shown as a badge);
   - a short "How to read this" panel and the run's provenance (commit, seeds, parameters).
   Charts as inline SVG generated in Python (matplotlib SVG output or hand-built SVG); light
   vanilla JS only for hover tooltips and filtering the decision log; colour palette and
   accessibility as in the WP7 figures (legend + direct labels, not colour alone), readable
   when printed. File size ≤ 2 MB.
   Commit three example cockpits under `docs/dashboard/` (generated by a script, Polish labels):
   a J30 run where Sentinel is on time and NoReaction is late, a J30 run with an escalation at
   Λ = 2, and a J60 run with overtime — chosen by a deterministic query over the WP5 results.
2. **Release** `sentinel release --version 1.0.0` builds `dist/sentinel-1.0.0.zip` from
   `git archive` of `HEAD` (tracked files only: code, configs, docs, committed results and
   bundles, `paper/generated/`, example cockpits), plus a generated `RELEASE.md` (contents, how
   to install with uv, fetch PSPLIB, run tests, `reproduce --check`, open the cockpits, and
   where the article and the report will be added), refusing a dirty tree; `--include PATH`
   adds extra files under `docs/deliverables/` (for the final PDFs later). Do **not** tag or
   publish; print the tag command for the owner.
3. **README** polish: one-paragraph overview, the architecture diagram as text, results at a
   glance generated from `paper/generated/numbers.tex` (a generated README section between
   markers, regenerated by `sentinel paper`), links to spec, ADRs, reports, cockpits.
4. **Tests**: cockpit generation on `tiny.sm` and a J30 smoke (HTML parses, contains every
