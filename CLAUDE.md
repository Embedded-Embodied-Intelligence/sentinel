# CLAUDE.md — Sentinel

Read this file at the start of every session. It is the constitution of the project.

## What this project is

Sentinel is a research prototype for **AI-driven project management**: a single agent that
monitors a project under uncertainty, detects threats to explicit goals (deadline, budget,
plan stability) and selects interventions by **simulating their outcomes before acting**.

- **Core A (advisor):** project model, RCPSP scheduling (SGS heuristics, CP-SAT), Monte Carlo
  risk forecasts, recommendations.
- **Goal B (Sentinel):** a goal-driven rollout agent with a permission gate, evaluated against
  classical predictive-reactive policies on PSPLIB instances extended with disruptions.
- The LLM has three narrow roles only: parse unstructured events, propose candidate actions in a
  fixed JSON grammar, explain decisions. It never decides and never runs inside rollouts.

Deliverables: a reproducible code base, an LNCS article (English) and a course report (Polish).
Deadline: 2026-12-02.

## How we work

- Work arrives as a **WP prompt** in XML tags (`<context>`, `<task>`, `<constraints>`,
  `<acceptance_criteria>`, `<report_format>`). Do exactly that scope.
- Touch only files the WP needs. No drive-by refactors, no new features outside scope.
- If the spec is ambiguous, contradictory or seems wrong: use the `spec-guard` skill. Never
  change model semantics silently and never edit `docs/spec/` unless the WP says so.
- Architectural choices not covered by the spec: record them with the `adr` skill.
- Finish every WP with the `wp-report` skill: `docs/reports/WPx.md`, then commit and push.

## Invariants (non-negotiable)

1. **Reproducibility.** All randomness flows through `numpy.random.Generator` objects created
   from explicit seeds. No global `random`/`np.random` state. Seeds are recorded in outputs.
   Compared policies use **common random numbers** (identical seeds).
2. **Results come only from code.** Every experiment runs from a config file in `configs/`
   through the experiment runner and writes a manifest (see `experiment-run` skill). Never edit
   result files by hand. Tables and figures for the papers are generated by scripts.
3. **LLM isolation.** All LLM calls go through `sentinel.llm` with record/replay caching and
   JSON-schema-validated outputs. No LLM calls in rollouts or simulation loops. Prompts and LLM
   data are in **English**.
4. **Secrets never enter git.** Keys live only in `.env` (gitignored). Never print, log or
   commit keys. `.env.example` lists variable names without values.
5. **Data policy.** Benchmark data (PSPLIB) is downloaded by `scripts/fetch_psplib.py` into
   `data/` (gitignored), never committed. Small result files are committed; large raw outputs
   are not (they are reproducible from code + seeds). No Git LFS.
6. **Feasibility is checked, not assumed.** Every schedule produced anywhere passes
   `validate_schedule` in tests and in experiment runners.
7. **Privacy by design.** The model stores worker *availability* only, never reasons for
   absence (GDPR Art. 9).

## Quality gate (all must pass before every commit)

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -q
```

- Python 3.12, full type hints, `mypy` clean, `ruff` clean.
- Pydantic v2 models for domain data; frozen where values must not change.
- Pure functions for algorithms; I/O at the edges (`data/`, `experiments/`, `cli.py`).
- Tests: unit tests without network; tests that need downloaded data use `@pytest.mark.data`
  and skip cleanly when data is absent.
- Docstrings: one line stating what and, for algorithms, a reference (e.g. "Kolisch 1996").

## Machine and budget awareness

- Server: Intel i5-6600K (4 cores), 20 GB RAM for WSL2, GTX 1060 6 GB. Be CPU-frugal.
- Anything expected to run longer than ~10 minutes: do **not** run it in the session. Implement
  a `--limit` smoke mode, run that, and put the exact full command in the WP report so the
  user runs it in `tmux`.
- The user is on a Claude Pro plan: keep context small. Do not read large data files whole;
  inspect with `head`, `wc`, targeted reads. Keep terminal output short.

## Git
